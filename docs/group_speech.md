# 群聊发言统计

仅统计群 `798977395`。每条有消息 ID 的群消息计一次，不区分文字、链接、表情、图片、文件、卡片或转发；一条消息中的多个消息段仍只计一次，合并转发不展开计数。群文件消息计一次，上传通知、撤回通知等非消息事件不另计。包含机器人自身的群消息，不排除任何群成员。

统计周期为北京时间上周日 22:00（含）至本周日 22:00（不含），完整七天。首次启动补读当前统计周；每次 WS 连接成功立即补读，此后每五分钟同步一次，汇总前再次同步。按消息 ID 去重，历史补读不执行旧命令或触发其他业务。

数据存放于 `runtime/databases/group_speech.sqlite3`，只保存消息 ID、发言者和时间，不保存消息正文。数据库写入在线程中执行。历史分页失败、游标停滞、字段不完整时不推进同步水位，也不发送未完成的汇总，稍后重试。

NapCat 在历史末尾仅返回同一条游标消息时，按可用历史耗尽处理；首期若因此无法覆盖完整七天，报告注明最早可读时间，不把机器人加入前的记录视为完整。2026-10-30 现场检查：该群机器人入群时间为 10 月 26 日 18:31，接口最早可读历史为同日 18:27，因此首期此前数据不可补回。

周日 22:00 起检查汇总，正常运行时最多约 15 秒后开始同步和发送。以汇总时完整成员列表为名单，包含零发言成员，逐人列出群名片/昵称、QQ 号及发言数，筛选条件为严格小于 50 条。发送给现有 `ADMIN_USERS` 中的全部管理员，长名单自动拆分私聊发送。若当时离线，恢复后先补历史再补发；多周离线时逐周补发，但历史各周的成员名单无法追溯，使用补发时的现有成员列表。

报告内容和每个管理员已确认送达的分段进度会持久化，重启后跳过已确认的分段。发送未确认时重试；QQ 已接收但响应丢失，或断电恰好发生在发送成功与保存确认之间，仍可能重复一个分段，无法在两个独立系统间保证严格一次送达。

历史完整性依赖 NapCat 实际返回的数据，按本机已验证的历史接口补读；接口若静默遗漏消息，统计端无法独立识别。已记录的消息撤回后仍算一次发言。不自动修改 NapCat 配置或权限。

针对性检查：`python -B -m pytest -o addopts='' -q -p no:cacheprovider --basetemp runtime/test_group_speech test/unit/test_group_speech.py test/unit/test_client_message_stream.py test/unit/test_client_lifecycle.py`。测试使用虚拟 OneBot，不向真实账号发消息。
