# 群聊自动反广告

此功能默认对所有群关闭。管理员在需要试用的群内使用：

- `/kick on`：开启本群记录和自动审核。
- `/kick off`：立即停止本群后续记录和未发送的处置动作。
- `/kick status`：查看本群开关、审核服务状态和 Bot 当前群身份。

命令要求操作者具有个人 Bot 权限 2 或 3 级；`GROUP_LEVEL` 对全群的提级不能授权这些命令。开启前还会检查 Bot 是群管理员或群主、文本模型和视觉服务已就绪，并确认存在可信的管理员证据接收人。Bot 失去管理员身份后仍可关闭功能。

## 审核和处置

六项筛选信号为低群等级、20 秒内至少 2 条且合计至少 100 个非空白文字、外链、图片、有限广告话术和转群引导。低等级只使用 OneBot 群成员资料中的 `level`。至少命中 3 项才进入模型复核；筛选票本身不会处罚。模型必须基于当前目标在本群最近 30 分钟内的消息和全部图片，返回可验证的违规证据。无法确认、图片或模型处理失败、证据不完整时保持静默，不发管理员复核请求。

3/6 是首版工程阈值，尚未通过实际数据验证或调优，不代表识别概率。

确认违规后，系统按顺序将已记录的半小时原始消息分批合并转发给一位管理员，在群内发送固定原因和申诉说明，再检查成员身份并尝试移出群，最后只撤回模型证据指向的消息。API 失败或超时不会盲目重试；回包未确认时不会声称动作成功。`/kick off` 不能撤回已经发给 QQ 服务器的请求。

纯图片消息若未达到筛选门槛，不会单独触发识图。首次开启之前、Bot 离线、断线或功能关闭期间没有收到的消息无法补齐；证据头会标记首次开启或采集缺口。

## 管理员接收人与数据

默认接收人为现有 `ADMIN_USERS` 中 QQ 号最小的一位。可通过唯一可选配置 `KICK_AUDIT_QQ` 指定一位接收人；该号码必须属于 `ADMIN_USERS` 或个人 Bot 权限 3 级，否则拒绝开启。私聊及合并转发是否被当前 NapCat 接受仍需现场验证。

只在已开启的群保存消息段和纯文本到独立 SQLite 数据库；普通消息约 45 分钟后清理。明确处置案卷及其证据快照保留 7 天，其他案卷元数据保留 24 小时。开启期间，目标消息的文本会发送到现有 DeepSeek 文本服务，图片会发送到现有视觉服务；这些服务必须按群内容的敏感程度配置。

## 验证情况

本地自动化测试使用 Fake OneBot、Fake 模型和临时 SQLite，覆盖成功处置顺序和不确定时零外部动作。没有连接真实 QQ 群、执行真人移群、调用生产模型或验证真实 NapCat 的合并转发扩展。部署时须确认连接此 Bot 的 NapCat OneBot WebSocket Server 使用 `messagePostFormat: "array"`，并在受控测试群确认图片、@ 和引用以独立消息段上报；仅根据配置不能视为现场验收。首次使用前请在受控测试群验证 OneBot 版本、管理员私聊合并转发字段、群提示、移群权限和撤回权限；不要用真人踢人测试生产群。
