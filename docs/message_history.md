# 缺失上下文与历史消息组件

`MessageHistoryService` 为群聊和私聊提供共用的有界历史读取。它只获取、校验和返回消息，不执行历史命令，不触发通知、审核、视觉下载或长期记忆抽取，不保存消息正文。

## aichat 恢复

- aichat 按当前已验证的群号或私聊对象按需补取，覆盖进程重启、WS 重连及 QQ 离线后的上下文缺口。连接生命周期或离线心跳使恢复缓存失效，不扫描全部群、联系人或全部历史。
- 群聊使用 `get_group_msg_history`，私聊使用 `get_friend_msg_history`。校验群号、机器人身份、作者与私聊目标；跨会话、作者冲突或不完整数据不能进入上下文。
- 沿用 aichat 的 300 条上限和 30 分钟窗口；历史与实时上下文按消息 ID 去重，并与当前 profile 的聊天历史共用消息预算。Windows 参数不足时裁剪旧历史和补取内容，保留当前请求与顶层引用。
- 同会话并发补取合并；恢复含排队在内最多等待 8 秒。正常结果缓存最多 5 分钟，失败/不完整结果短暂缓存后重试。只使用当前请求时间之前的可核验历史，不能把请求后到的消息放进旧请求。
- 管理员独立任务历史保持隔离，同时可读取经过现有 `message_allowed` 过滤的当前 QQ 会话近期发言。补取结果仅作为资料，不写入管理员独立历史，也不自动写入长期记忆。
- `runtime/state/context_history_state.json` 只保存记忆切换/清除边界、已确认回复的消息 ID、请求者与时间。`/memory on/off/new/clear` 及 group 开关/清除更新恢复边界；重复开启不清空上下文。恢复不能越过边界或成员退出策略。
- 群内旧 bot 回复若没有可信请求者归属会跳过；新 aichat 回复在发送确认后记录归属，可跨重启恢复。私聊 bot 回复归属已验证的当前对象。元数据写入失败不会使已送达回复再次补发。

## 每周发言统计

群 `798977395` 的每周不足 50 条统计复用同一实例的分页读取接口，保留原有 SQLite 消息身份、统计周期、断点水位和私聊报告规则。统计按完整七天读取，不受聊天的 300 条正文窗口限制，但只将消息 ID、作者和时间交给原有计数存储。

分页失败、字段不完整或非末尾游标停滞时不推进统计覆盖水位；NapCat 重复返回唯一末尾锚点时保留原有最早可读历史提示。接口不可读、已过期或已删除的数据无法恢复，组件不宣称历史绝对完整。

## 当前会话回复

管理员保留完整工具权限，使用群聊/私聊人物设定。普通接话、回复某人由模型直接生成最终内容，当前会话统一由 bot 发送。需要 @ 时返回 `{"qq_reply":{"text":"不用谢","at":[2629146571]}}`；bot 仅允许当前消息明确提及、历史或引用中已核验的目标，将其渲染为 QQ 消息。纯文本输出保持兼容，JSON 正文中的 CQ 控制串转义为普通文字。

真实本机、文件及跨会话任务仍可使用工具；不能把当前会话的一句回复转成 Bash/HTTP 代发，再追加执行报告。管理员 agent 不再引入通用 coding base prompt 的“默认执行”倾向。

## 验证

相关组合回归 350 项通过，记忆专项 111 项通过（部分用例重合）。覆盖新实例恢复群/私聊、成员退出、清除边界、发送归属、请求并发、重连、时间/条数及 Windows 参数预算、统计分页与断点报告。真实群/私聊历史接口只读校验通过；完整管理员工具配置下，“回学渣一句不用谢”的真实 Kimi 验收返回可渲染的 @ 回复且没有工具调用，未向 QQ 发送验收消息。
